# Run AI UI Walkthrough

AI 驱动真实浏览器逐页走查时，操作失效和状态误判是常态而非例外：点击落空、键入丢失、弹层叠开、同一查询前后行为不一致。核心纪律是四条：每步限时、先核对状态再重试、输入留降级路径、用零请求证据做无破坏验证。

## 每步一个时间盒

- 给每个走查步骤设定预期时间（表单级验证 1~3 分钟量级，页面级放宽），超时立刻停止重试，转入诊断或降级；「再试一次」不是处理方式。
- 同一操作失败两次即视为该方法在当前页面失效，第三次必须换路径：换定位策略、换输入方式或换数据组合。时间盒可按页面复杂度调整，但「失败两次换路径」不放宽。

## 状态核对先于重试

- 操作「没反应」时先列出全部可见弹层的原始清单（不做可见性过滤），一次性核对真实状态；多层弹窗叠开是误判高发区——按文本特征全局定位会命中错误弹层的同名按钮，并把「弹层还在」误读成「已关闭」。
- 可见性过滤条件（如 offsetParent、尺寸大于零）在叠层与动画渲染下不稳定，同一脚本前后两次结果可能不同；定位收窄到具体弹层元素内部再找按钮和输入框，不做页面级全局查找。
- 导航后页面处于装配期，立即读取会报「文档已变化」；重取一次状态再操作，不把它当作操作失败。

## 输入模拟多路径互备

- 程序化设值（value setter + 输入事件）与真实按键注入是两条独立路径，各自都可能失效且行为不稳定（焦点已设置但按键未落框、框架组件不响应合成事件、setter 类型不匹配报错）。一种失效立即换另一种。
- 两条路都失效时降级保主线：改用全量结果列表直接选中目标行、换检索条件或换一组测试数据；走查的目的是验证页面行为，不是征服某个输入框。
- 设值旁路会绕过 maxlength 等浏览器限制：强设超长成功不代表用户路径可用。以元素属性（maxLength）和界面计数器为证据，旁路结果不作为通过或缺陷依据。
- 「查询后列表未过滤」先怀疑输入从未生效、实际查的是空条件全量，把输入框实际值与请求参数一起核对后再定性；否则容易把自动化失灵误报成页面缺陷。

## 无破坏验证

- 需要验证「超长/非法输入被拦截」又不允许改数据时，故意走失败路径：非法输入后点提交，预期表现是界面报错且网络层零请求；用请求清单证明「没有发出」，比描述界面现象更硬，同时天然不产生数据变更。
- 走查默认不保存、不提交、不审批；表单以取消收场。凡是触发过提交类按钮的验证，收场前核对单据状态未变。

## 失效边界

- 本方法针对 AI 自动化操作不可靠导致的卡顿；诊断确认是产品缺陷（真实用户路径可复现）时转入缺陷流程，不用降级路径掩盖缺陷。
- 验证覆盖不到的链路（如需要多角色审批才能触发的写库行为）如实标注依据来源（本地已验/接口层已验），不宣称页面已验证。
